# Hermes 微信渠道回复策略

## 1. 目的与适用范围

本文规定 Hermes 通过微信 iLink/ClawBot 处理项目相关任务时的用户可见回复策略，目标是减少过程消息、避免触发微信限流，并确保最终文本和媒体结果可被可靠交付。

本策略只约束 `weixin` 渠道，不修改全局 `SOUL.md`，不影响 Hermes 桌面端、CLI 或其他消息渠道，也不改变房源技能本身的通用工作流。

Hermes 的实际运行配置位于 `%LOCALAPPDATA%\hermes\config.yaml`。仓库只保存配置规范，不保存真实微信用户 ID、Token、API Key 或其他运行时凭据。

## 2. 控制边界

微信回复由三层共同控制：

| 层级 | 负责内容 | 本策略中的处理方式 |
| --- | --- | --- |
| 网关显示配置 | `Working` 心跳、工具进度、流式输出和中间 commentary | 使用 `display.platforms.weixin` 强制关闭 |
| Hermes 渠道指令 | 回复语言、回复时机、允许展示的信息和最终回复结构 | 使用 `platforms.weixin.channel_overrides` 绑定到具体微信会话 |
| 投递实现 | 限流重试、最终消息优先级、文本与媒体投递确认 | 需要 Hermes 网关代码提供可靠投递保障 |

提示词不能关闭网关自行生成的 `Working — iteration ...` 消息，因此显示配置和渠道指令必须同时设置。提示词也不能替代投递重试、媒体确认等代码级保障。

## 3. 微信专用配置

将以下内容合并到 `%LOCALAPPDATA%\hermes\config.yaml`。不要覆盖配置中已有的模型、MCP 服务或其他渠道设置。

```yaml
display:
  platforms:
    weixin:
      tool_progress: "off"
      interim_assistant_messages: false
      long_running_notifications: false
      busy_ack_detail: false
      streaming: false
      show_reasoning: false

platforms:
  weixin:
    gateway_restart_notification: false
    channel_overrides:
      "<WEIXIN_CHAT_ID>":
        system_prompt: |
          这是微信私聊渠道，必须遵守以下用户可见回复协议：

          1. 所有用户可见内容使用简体中文。
          2. 不得发送内部推理、英文工作旁白、工具名称、iteration、命令、
             文件路径、进程信息、模型供应商、环境变量或密钥处理过程。
          3. 预计 30 秒内完成的任务不发送中间消息，只发送最终结果。
          4. 预计超过 30 秒时，收到任务后最多发送一条简短确认。
          5. 连续执行超过 5 分钟仍未完成时，最多发送一条状态更新；
             此后每 10 分钟最多一条，禁止逐步骤汇报。
          6. 工具调用、后台任务启动、缓存命中和自动重试均静默处理。
          7. 只有缺少必要信息、需要用户授权或自动重试用尽时，才立即联系用户。
          8. 房源海报交付时，只发送一条不超过 120 个汉字的摘要和一张海报；
             摘要只包含位置、预算、候选数量以及“回复编号查看详情”。
             不得在微信正文中逐套列出 Top 20 房源，不得重复海报已有内容。
          9. 单套详情图交付时，正文不超过 100 个汉字，只包含编号、房源名、
             户型、面积、租金和下一步操作，不复述图片中的完整字段。
          10. 在文本和附件确认投递成功前，不得声称已经发送或任务已经完成。
          11. 最终回复保持简洁，不复述内部执行过程。
    extra:
      split_multiline_messages: false
```

`<WEIXIN_CHAT_ID>` 必须替换为目标微信会话 ID。可从 `%LOCALAPPDATA%\hermes\channel_directory.json` 查询，但不得将真实 ID 提交到仓库。

Hermes 当前不支持 `channel_overrides` 通配符。新增微信联系人或会话时，需要为新的 `chat_id` 增加相同规则。如果需要让所有现有及未来微信会话自动继承同一提示词，应在 Hermes 中增加平台级 `system_prompt` 能力，而不是改用全局 `SOUL.md`。

## 4. 回复时机与内容

| 场景 | 回复时机 | 用户可见内容 |
| --- | --- | --- |
| 预计 30 秒内完成 | 完成后 | 仅最终结果 |
| 预计超过 30 秒 | 接收任务后 | 最多一条中文确认，包含任务摘要和预计耗时 |
| 执行超过 5 分钟 | 第 5 分钟左右 | 最多一条中文状态，说明当前业务阶段，不展示工具或内部实现 |
| 长任务继续执行 | 此后每 10 分钟最多一次 | 仅在确有新进展时更新；无新进展则保持静默 |
| 缺少必要参数 | 发现后立即 | 一次提出最少且明确的问题 |
| 需要授权 | 执行前 | 说明将执行的动作、影响和所需授权 |
| 可恢复异常 | 自动重试期间 | 静默处理 |
| 确定失败 | 自动重试用尽后 | 说明未完成的业务步骤、用户影响和下一步，不暴露内部堆栈或密钥信息 |
| 成功完成 | 文本和附件均准备完成后 | 一次性发送结果摘要、附件和下一步操作 |

推荐确认消息：

> 已收到，正在筛选双桥路南一街附近约 2000 元/月的房源，预计需要 3–8 分钟。

推荐长任务状态：

> 已完成房源采集，正在进行最终筛选和海报生成，请稍候。

禁止发送以下内容：

- `Working — iteration 13/150` 等运行时心跳；
- “Let me check...”“Pipeline launched...”等英文内部旁白；
- 工具名、命令、进程号、缓存目录和本地文件路径；
- 环境变量名称及密钥的读取、复制、校验或临时文件处理过程；
- 每一步工具调用成功或失败的流水账。

## 5. 生效步骤

1. 备份 `%LOCALAPPDATA%\hermes\config.yaml`。
2. 合并微信专用显示配置和目标会话的 `channel_overrides`，保留其他现有设置。
3. 按本机部署方式重启 Hermes Gateway。
4. 在目标微信会话发送 `/reset`，确保旧会话中冻结的系统提示词不再继续使用。
5. 发送一个预计运行 5 分钟以上的测试任务，按第 6 节验收。

## 6. 验收标准

- 一个持续约 10 分钟、包含大量工具调用的任务，微信侧除最终回复外最多出现两条状态消息。
- 微信侧不出现英文内部旁白、iteration、工具名、命令、路径、进程或密钥处理信息。
- 30 秒内完成的任务只产生一条最终回复。
- 最终回复使用简体中文，并包含查询条件、结果摘要、附件和明确的下一步操作。
- 微信返回限流错误时，过程消息不与最终消息争抢发送额度。
- 最终文本和媒体分别有成功确认；任一投递失败时不得向用户宣称完整交付成功。
- 限流解除后，无需重启网关即可自动补投失败的最终文本和媒体。

## 7. 已知限制与代码改进项

配置和渠道提示词只能减少噪声，不能独立保证可靠投递。Hermes 网关还应实现：

- 最终文本和媒体使用高于进度消息的发送优先级；
- iLink 返回限流错误时，将最终结果置为可重试状态并按退避策略补投；
- 存活网关能够重试自己拥有的失败投递记录，而不是必须等待网关重启；
- 媒体附件写入投递台账，并校验 iLink 响应中的 `ret`/`errcode`；
- 后台任务通过受控环境变量继承所需凭据，不读取网关进程环境，也不创建明文临时密钥文件。
