# ADR-0001：采用渐进式平台化，而非整体重构

- 状态：已接受
- 日期：2026-07-29

## 背景

仓库已经具备 Monorepo、独立服务目录和 DDD 风格分层，但网关、统一身份、服务目录、数据库迁移、可观测性和生产编排仍不完整。当前真正需要身份能力的业务服务只有 `store_media`。

## 决策

保留现有 Monorepo 和服务内分层，不进行整体重写。采用以下边界：

1. 每个业务服务独占数据与上传文件，禁止跨库访问；同步调用使用版本化 HTTP 契约，异步调用使用事件契约。
2. `store_media` 先在自身边界内实现身份和 RBAC，授权策略与存储分离。出现第二个需要登录的服务或需要企业 SSO 时，提取 `identity_access` 服务，签发短期令牌；网关只验证令牌，不承载业务授权。
3. `services/catalog.yaml` 作为服务元数据来源，后续 CI 校验健康检查、配置前缀、Docker 构建和契约兼容性。
4. 网关仅负责入口路由、统一认证、请求 ID、基础限流和访问日志。区域/门店范围等业务授权仍由服务执行。
5. SQLite 和本地文件适用于单实例初期运行。需要多实例或高可用时，媒体迁移到对象存储，元数据迁移到 PostgreSQL，并通过迁移脚本管理表结构。

## 分阶段演进

### 当前阶段

- 服务可独立启动、测试和持久化；
- 上传做内容特征和大小校验；
- 密码使用 PBKDF2，服务端保存不透明会话令牌摘要；
- 角色权限按区域和门店收敛。

### 下一阶段（第二个受保护服务之前）

- 实现 API 网关反向代理、请求 ID、结构化日志和统一错误格式；
- 建立 CI：单元测试、契约测试、镜像构建、依赖与密钥扫描；
- 选择 PostgreSQL、对象存储并引入正式迁移工具；
- 提取统一身份服务或对接企业身份源，保留各业务服务的细粒度授权判断。

### 规模化阶段

- 引入 OpenTelemetry 指标、日志和链路追踪；
- 以队列处理视频转码、缩略图、病毒扫描和发布事件；
- 根据 SLO 和团队边界决定是否拆分服务，避免按技术层拆出大量相互依赖的小服务。

## 结果

当前需求可以低成本上线，同时保留清晰的提取点。代价是 `store_media` 的本地身份暂时不能被其他服务直接复用；这是显式的过渡状态，禁止复制其用户表到其他服务。
