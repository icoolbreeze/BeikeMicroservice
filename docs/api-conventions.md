# API 约定（草案）

各服务对外 HTTP 接口遵循的统一约定。当前阶段为约定文档，接口尚未实现。

## 版本与前缀

- 所有业务端点挂载在 `/api/v1` 前缀下；
- 版本升级通过新增 `v2` 目录实现，不破坏旧版本。

## 统一响应结构

```json
{ "code": 0, "message": "ok", "data": {} }
```

- `code`：0 表示成功，非 0 为业务/系统错误码（错误码表待补充）；
- `data`：成功时承载业务数据，失败时可为空。

## 异步任务模式

耗时操作（如证件信息提取、房源验证）采用任务模式：

1. `POST /api/v1/<resource>/jobs` 创建任务，返回 `job_id`；
2. `GET /api/v1/jobs/{job_id}` 轮询任务状态与结果；
3. 任务状态枚举：`pending` / `running` / `succeeded` / `failed`。

## 命名

- 路径使用 kebab-case，字段使用 snake_case；
- 写操作具有幂等性要求（重复提交不产生重复任务，具体机制待设计）。

## 安全要求

- 响应与日志中的证件编码、业务件号等敏感字段必须脱敏（见 `security.md`）；
- 所有写操作需要记录审计事件（操作者、时间、动作、结果）。
