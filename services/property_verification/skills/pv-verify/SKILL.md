# 查档核验（pv-mcp 工作流）

用 pv-mcp 工具对不动产权证照片执行"上传 → 轮询 → 下载截图"核验。
核验流水线在云端服务执行，本机工具只是编排。

> 本技能与 `app/mcp/`（pv-mcp）配套使用：先按目标 agent 的 MCP 注册方式
> 加载 pv-mcp（仓库根 `.mcp.json` 的 `property-verification` 条目可供参考），
> 再把本目录复制到该 agent 的技能目录。

## 标准流程

1. **定位图片文件**
   - 用户给出路径（如 `D:\证.jpg`）时直接用；
   - 用户只粘贴了图片、没给路径时：按当前 agent 处理附件的方式定位本地文件
     （常见的如系统临时目录、下载目录中最近修改的 jpg/png），
     找不到就问用户要本地绝对路径（本工具需要文件路径，不能直接收附件字节）。

2. **提交核验**：`pv_verify_submit(image_path=绝对路径)`
   - 返回 `job_id`、剩余额度；限流 2 次/分钟，429 报错时告知用户稍后再试。

3. **轮询状态**：`pv_verify_status(job_id)`，间隔 5-10 秒，
   直到 `status` 为 `succeeded` 或 `failed`（通常 1-3 分钟，模型重试+兜底可能更久）。
   - `failed`：把 `error` 原文告诉用户（如"识别失败请换清晰照片"）。

4. **获取数据**：`pv_verify_result(job_id)`
   - 返回官方蓉e办查询的**完整原始数据**：`headers`（表头，按列顺序）、
     `row`（数据行，与表头一一对应）、`fields`（逐列字段映射）。
   - 响应同时含 `artifacts` 产物清单，每个产物 `url` 为**房产证查档截图**的绝对
     下载链接（panel=查档结果区域截图，full=整页查档截图，zip=全部产物打包）；
     需要转发给最终用户时改用 `pv_verify_share_link` 生成短期签名链接。
   - 本工具不提供任何总结/结论；**由你根据 fields 自行总结**并向用户汇报。
   - 核验目的即判断房产是否被查封：看 `fields.是否查封`（是/否）；
     相邻的 `fields.是否抵押`、`区域`、`街道`、`栋号`、`套内面积`、`房屋用途`
     等一并汇报。
   - `result` 为 null 表示数据未生成（任务未完成或表格列数错位）。

5. **下载截图**：`pv_verify_download(job_id, spec="panel")`
   - `panel` 区域截图优先；需要整页用 `full`；全部产物用 `zip`。
   - 返回本地绝对路径，供用户人工核对。

6. **转发截图（可选）**：需要把截图链接给最终用户（如微信/网页）时，
   用 `pv_verify_share_link(job_id, spec, ttl=600)` 生成**短期签名链接**
   （默认 10 分钟，过期即失效），不要直接转发原始下载地址。
   链接是明文 HTTP，请勿二次转发给无关第三方。

7. **汇报**：根据 `fields` 原始数据自行总结后回答用户（是否查封=是/否、是否抵押、
   区域/街道/门牌号/套内面积/房屋用途等），并给出截图路径/短期链接供人工复核；
   提醒关键字段人工复核。

## 隐私与安全

- 证件照片属**敏感个人信息**：核验完成后提醒用户删除本地证件副本
  （服务端原件核验后即删，仅保留产物截图）；
- `job_id` 即访问凭据，不要写进文档或发到外部；
- 仅用于本公司业务范围内房源核验，勿替他人证件核验。

## 常见错误

- `任务不存在或已过期`：服务重启后任务记录清空，重新提交即可；
- `请求过于频繁`：命中 2 次/分钟限流，等约 1 分钟再试；
- `产物不存在或已失效`：任务尚未 succeeded，先等轮询到终态。
